# T21: telefon + OTP, plan de implementare

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vizitatorii și Localnicii intră în aplicația mobilă doar cu telefon + cod OTP. Numerele `0799000xxx` sunt de demo; celelalte primesc SMS prin Twilio Verify.

**Architecture:** BE: `PhoneNumbers` (normalizare), `OtpService` (limite, coduri locale, Twilio), endpoint-uri `/auth/otp/*`, migrarea V11. FE: fluxul cu 3 pași în aplicația mobilă. Infra: secretul Twilio pe task-ul API.

**Tech Stack:** Spring Boot 3.3 / Java 21 (`RestClient`, JJWT, Flyway), Vue 3.5, Terraform.

**Spec:** `docs/superpowers/specs/2026-11-07-phone-otp-design.md`

## Global Constraints
- Branch `feat/T21-phone-otp` în BE, FE, Infrastructure și Plan (worktree-uri `_wt/*-T21`). Merge: Infra (apply) → BE → FE → Plan.
- Commit-uri în engleză, fără `Co-Authored-By`. Mesajele de eroare din API sunt în engleză (ca restul).
- Fără SDK nou: Twilio prin `RestClient`, cu Basic auth (`account-sid:auth-token`). URL-ul de bază e configurabil, ca testele să-l mock-uiască.
- **Valori:** cod de 6 cifre, valabil 5 minute; 60 s între cereri; 5 coduri pe zi pe număr; 5 încercări pe cod; `signupToken` valabil 15 minute.
- **Demo:** `^\+40799000\d{3}$`.
- Secretele nu ajung în git și nici în chat; `terraform plan` se aprobă de Zoltan.

## Review Focus
1. **Număr de enumerare:** `request` și `verify` nu au voie să spună dacă un număr are cont înainte de un cod corect.
2. **Un cod demo** nu se poate folosi pentru un număr real (provider-ul se decide după număr, nu după ce trimite clientul).
3. **`signupToken`** nu e acceptat ca token de autentificare: `JwtAuthFilter` respinge `purpose=signup`.
4. **Conturile din seed** (bilete, puncte) rămân legate după migrare: numerele se pun prin `UPDATE`, nu prin rânduri noi.
5. **Twilio indisponibil sau trial** (număr neverificat): erori clare (503 / 400), nu 500.

### Task 4: BE, `OtpService`
**Files:** `service/auth/OtpService.java` + `OtpServiceTest`; o excepție nouă `TooManyRequestsException` (429, cu `retryAfterSeconds` în ProblemDetail; adaugă și un handler).
**Produces:**
- `record RequestResult(int retryAfterSeconds, String demoCode)`;
- `RequestResult request(String rawPhone)`;
- `String verify(String rawPhone, String code)`, care întoarce telefonul E.164 verificat sau aruncă 401.
- [ ] **Teste (cu `Clock` fix):**
  - demo: `request` întoarce un `demoCode` de 6 cifre, iar `verify` cu el trece o singură dată (a doua oară → 401);
  - a doua cerere sub 60 s → 429, cu `retryAfterSeconds` în (0, 60];
  - a șasea cerere din aceeași zi → 429;
  - un cod expirat (după 5 minute) → 401;
  - 5 coduri greșite → al șaselea, chiar corect → 401;
  - un număr real apelează `twilio.start` și `twilio.check` și nu întoarce `demoCode`;
  - un cod demo pe un număr real nu e acceptat;
  - Twilio neconfigurat → 503.
- [ ] Implementare, commit.
